强化编程与软件工程能力，支持大型代码库开发、终端操作及端到端项目等复杂工程场景

流式响应采用服务器发送事件（SSE）格式，每个事件包含：

choices[0].delta.content: 增量文本内容
choices[0].delta.reasoning_content: 增量思考内容
choices[0].finish_reason: 完成原因（仅在最后一个chunk中出现）
usage: 令牌使用统计（仅在最后一个chunk中出现）
工具调用
Function Calling 允许模型通过调用外部工具获取实时数据或执行特定操作。模型不会直接执行函数，而是返回待调用的函数名称及参数；用户代码完成调用后，将执行结果传回模型，由模型生成最终的自然语言回答。

调用流程：

用户提问 → 模型返回 tool_calls（包含函数名称和参数）
用户代码执行函数 → 以 role: tool 消息传回结果
模型根据结果生成最终回答
完整闭环流程：模型调用 → 模型返回 → 本地执行 → 工具回传 → 最终模型返回

模型调用：

复制
{
  "model": "glm-5.3",
  "messages": [
    {"role": "user", "content": "今天上海天气怎么样？"}
  ],
  "thinking": { "type": "enabled" },
  "reasoning_effort": "low",
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "get_weather",
        "description": "查询指定城市的天气信息",
        "parameters": {
          "type": "object",
          "properties": {"city": {"type": "string", "description": "城市名称"}},
          "required": ["city"]
        }
      }
    }
  ],
  "tool_choice": "auto",
  "stream": false
}
模型返回： 按照模型返回获取对应的 tool_call_id

本地执行： 业务侧根据模型返回的 function.name 和 function.arguments，调用对应的本地函数或外部 API

例如：

复制
//本地执行：
get_weather(city="上海")

//获取结果
{
  "city": "上海",
  "weather": "晴",
  "temperature": "29°C"
}
Function Calling 仅负责生成工具调用请求，不会自动执行实际函数。

工具回传：

工具执行完成后，将原始对话、模型返回的 tool_calls 以及工具执行结果一并发送给模型。

工具结果通过 role: "tool" 回传，并使用 tool_call_id 与对应的工具调用进行关联。

思考模式
模型始终开启思考，不能关闭。thinking.type 只接受 enabled（默认）。传入 disabled 请求会失败。用 reasoning_effort 设置思考强度，例如 "reasoning_effort": "high"。

参数说明：

字段	类型	必填	默认值	说明
thinking.type	string	—	enabled	思考开关。只接受 enabled
thinking.clear_thinking	boolean	—	true	true：忽略历史轮次的 reasoning_content
false：保留，且内容必须完整、未修改、顺序不变
reasoning_effort	string	—	max	推理力度。只接受 low、high、max
思考强度：

取值	说明
low	轻量推理。适合简单问答，以及从旧模型迁移时的起步档，延迟和输出 Token 更低
high	增强推理。适合一般分析和中等代码任务
max	深度推理（默认）。适合复杂编程、长程 Agent。Coding 任务使用此档

响应说明：

content：返回模型最终生成的回复内容
reasoning_content：模型输出的思维链内容。low 推理级别下的简短回答可能不返回该字段。无论该字段是否返回，思考 Token 均计入 usage.completion_tokens_details.reasoning_tokens
请求参数
字段	类型	必填	默认值	说明
model	string	✅	—	模型标识。固定为 glm-5.3
messages	array	✅	—	对话消息列表。role 可取 system、user、assistant 或 tool；上下文长度最高支持 1M Tokens
stream	boolean	—	false	是否以 SSE 流式返回。结束帧为 data: [DONE]
thinking	object	—	{"type":"enabled"}	思考模式配置。type 只接受 enabled
reasoning_effort	string	—	max	推理力度。只接受 low、high、max
do_sample	boolean	—	true	是否启用采样。true：按 temperature、top_p 采样；false：贪心解码，忽略 temperature 和 top_p。代码生成、翻译等要求稳定输出时建议 false
temperature	float	—	1.0	采样温度，范围 [0.0, 1.0]。与 top_p 一般只调一个
top_p	float	—	0.95	核采样，范围 [0.01, 1.0]
max_tokens	integer	—	65536	单次生成上限，范围 [1, 131072]。思考内容与回答共享该配额，建议不小于 1024
stop	array	—	—	停止词，最多 4 个。命中后立即停止
response_format	object	—	{"type":"text"}	输出格式。type 取 text 或 json_object
tools	array	—	—	可供模型调用的函数工具列表，最多 128 个
tool_choice	string	—	auto	工具选择策略。auto：由模型决定是否调用；none：不调用工具；required：必须返回 tool_calls
tool_stream	boolean	—	false	是否流式返回函数参数。须同时设置 stream: true
n	integer	—	1	生成候选条数，取值支持 [1, 4]

该模式保证输出是 JSON 对象。字段是否齐全仍需调用方校验

参数推荐
参数 / 实践	建议	说明
max_tokens	普通任务 2048～4096；思考模式建议 ≥ 4096	思考内容和回答共享 max_tokens。连通性检查可用更小值，正式任务不要低于 1024
stream	长文本生成建议开启	降低超时风险，改善首字体验

reasoning_effort	简单任务 low，复杂编程和 Agent 用 max	默认 max
